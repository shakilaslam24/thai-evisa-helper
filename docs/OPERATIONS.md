# DreamFly CRM — চালু রাখা, ব্যাকআপ ও সমস্যা সমাধান

সিস্টেম সার্ভারে বসানোর পর দৈনন্দিন যা যা লাগবে।

---

## এক নজরে সব কমান্ড

সার্ভারে লগইন করে প্রজেক্ট ফোল্ডারে গিয়ে চালাবেন।

| কাজ | কমান্ড |
| --- | --- |
| **সব ঠিক আছে কিনা দেখা** | `npm run doctor` |
| **ব্যাকআপ নেওয়া** | `npm run backup` |
| ব্যাকআপের তালিকা | `npm run backup -- --list` |
| **ডেটা ফিরিয়ে আনা** | `npm run restore -- --latest` |
| **আপডেট নেওয়া** | `npm run update` |
| অ্যাকাউন্ট তৈরি / পাসওয়ার্ড রিসেট | `npm run admin -- --email … --password '…'` |
| কোন অ্যাকাউন্ট আছে দেখা | `npm run admin -- --list` |
| সার্ভিস চালু আছে কিনা | `sudo systemctl status dreamfly` |
| সার্ভিস রিস্টার্ট | `sudo systemctl restart dreamfly` |
| লগ দেখা | `sudo journalctl -u dreamfly -n 100` |

## ১. স্বাস্থ্য পরীক্ষা — `npm run doctor`

সপ্তাহে একবার চালালেই যথেষ্ট। এক পলকে দেখায়:

```
[  OK  ] Database integrity       no corruption found
[  OK  ] Records                  leads: 412, customers: 180, case_files: 205 …
[  OK  ] Administrator accounts   1 active
[ WARN ] Disk space               8.2 GB free of 50 GB (16%)
[  OK  ] Document files           all 1,240 recorded document(s) present on disk
[  OK  ] Backups                  14 kept, newest 30/08/2026, 3:00 AM
```

**যা যা পরীক্ষা করে:**

- ডেটাবেস নষ্ট হয়েছে কিনা
- ডিস্কে জায়গা আছে কিনা (**১৫% এর নিচে গেলে সতর্ক করবে**)
- আপলোড করা ডকুমেন্ট সব ডিস্কে আছে কিনা
- ব্যাকআপ কত পুরনো (**৩ দিনের বেশি হলে FAIL**)
- অ্যাডমিন অ্যাকাউন্ট আছে কিনা

`FAIL` দেখলে ওই লাইনটা আমাকে পাঠাবেন।

## ২. ব্যাকআপ — সবচেয়ে জরুরি অভ্যাস

### হাতে নেওয়া

```bash
npm run backup
```

**সার্ভার বন্ধ করতে হয় না** — চালু অবস্থাতেই নিরাপদে নেয়।

কী কী রাখে:
- ডেটাবেসের নিরাপদ কপি (`backups/db/`)
- আপলোড করা সব ডকুমেন্ট (`backups/uploads/`) — শুধু নতুনগুলো কপি হয়, তাই দ্রুত
- শেষ **১৪টা** ব্যাকআপ রাখে, পুরনোগুলো নিজে থেকে মুছে যায়

### 🔴 রোজকার অটো-ব্যাকআপ চালু করুন

সার্ভারে একবার এটা চালান:

```bash
crontab -e
```

ফাইলের শেষে এই লাইনটা যোগ করে সেভ করুন (আপনার ফোল্ডারের পথ বসিয়ে):

```
0 3 * * * cd /home/dreamfly/dreamfly-crm && /usr/bin/npm run backup >> /var/log/dreamfly-backup.log 2>&1
```

এতে **প্রতি রাত ৩টায়** নিজে থেকে ব্যাকআপ হবে।

### ⚠️ সার্ভারের বাইরেও কপি রাখুন

সার্ভারের ভেতরের ব্যাকআপ সার্ভার নষ্ট হলে বাঁচাবে না। মাসে অন্তত একবার
নিজের ল্যাপটপে নামিয়ে রাখুন:

```bash
# আপনার ম্যাক থেকে চালাবেন
scp -r root@আপনার-সার্ভার-IP:/home/dreamfly/dreamfly-crm/backups ~/Desktop/dreamfly-backup
```

## ৩. ডেটা ফিরিয়ে আনা

ভুল করে কিছু মুছে ফেললে বা গোলমাল হলে:

```bash
# ১. আগে দেখুন কোন কোন ব্যাকআপ আছে
npm run backup -- --list

# ২. সার্ভিস বন্ধ করুন
sudo systemctl stop dreamfly

# ৩. সবচেয়ে নতুনটা ফিরিয়ে আনুন
npm run restore -- --latest
```

প্রথমবার এটা শুধু **সতর্কবার্তা দেখাবে, কিছু করবে না**। নিশ্চিত হলে:

```bash
npm run restore -- --latest --yes
sudo systemctl start dreamfly
```

**ভুল করে restore করে ফেললেও ভয় নেই** — বর্তমান ডেটাবেসটা
`backups/replaced/` ফোল্ডারে জমা থাকে, ওখান থেকে ফেরানো যায়।

> মনে রাখবেন: শেষ ব্যাকআপের পর যা যা ঢুকিয়েছেন, restore করলে সেগুলো হারাবে।
> তাই রোজকার অটো-ব্যাকআপটা চালু রাখা এত জরুরি।

## ৪. আপডেট নেওয়া

নতুন ফিচার বা বাগ ফিক্স এলে:

```bash
npm run update
```

এই একটা কমান্ড ৫টা কাজ করে:

1. **আগে ব্যাকআপ নেয়** — কিছু ভুল হলে ফেরার পথ থাকে
2. নতুন কোড নামায়
3. নতুন dependency ইনস্টল করে
4. নতুন সেটিংস/তালিকা যোগ করে (**আপনার নিজের বদলানো জিনিস নষ্ট হয় না**)
5. সার্ভিস রিস্টার্ট করে ও `doctor` চালিয়ে দেখায় সব ঠিক আছে কিনা

সার্ভিস চালু না হলে থেমে গিয়ে জানাবে, তখন লগ দেখবেন।

### আপডেটের পর কিছু ভাঙলে

```bash
sudo systemctl stop dreamfly
npm run restore -- --latest --yes
git checkout HEAD~1          # আগের ভার্সনে ফিরে যান
npm install --omit=dev
sudo systemctl start dreamfly
```

## ৫. সমস্যা হলে

| যা দেখছেন | কী করবেন |
| --- | --- |
| সাইট খুলছে না | `sudo systemctl status dreamfly` — বন্ধ থাকলে `sudo systemctl restart dreamfly` |
| রিস্টার্টেও চলছে না | `sudo journalctl -u dreamfly -n 100` — শেষ লাইনগুলো আমাকে পাঠান |
| "no space left on device" | `npm run doctor` → ডিস্ক ভরা। পুরনো ব্যাকআপ/ডকুমেন্ট সরান বা প্ল্যান বড় করুন |
| পেজ ধীর হয়ে গেছে | `npm run doctor` চালান, তারপর `sudo systemctl restart dreamfly` |
| লগইন হচ্ছে না | `npm run admin -- --list` → `npm run admin -- --email … --password '…'` |
| ডেটা গোলমাল | `npm run doctor` → Database integrity দেখুন → দরকারে restore |
| HTTPS মেয়াদ শেষ | `sudo certbot renew` |

### সার্ভার রিবুট হলে?

`systemd` সেটআপ থাকলে **নিজে থেকেই চালু হবে**, কিছু করতে হবে না।
যাচাই করতে: `sudo systemctl is-enabled dreamfly` → `enabled` দেখানো উচিত।

## ৭. সৎ কথা — কী আশা করবেন

**যা নির্ভরযোগ্য:** সিস্টেমটা গঠনে সরল — একটা Node প্রসেস আর একটা ডেটাবেস ফাইল।
আলাদা ডেটাবেস সার্ভার নেই, বাইরের কোনো সেবার উপর নির্ভরতা নেই। যত কম অংশ,
তত কম নষ্ট হওয়ার সুযোগ। `systemd` থাকলে সার্ভার রিবুট বা প্রসেস বন্ধ হলে
নিজে থেকেই ফিরে আসে।

**যা সৎভাবে বলা দরকার:** এটা নতুন সফটওয়্যার। পরীক্ষা করা হয়েছে, কিন্তু
বছরের পর বছর হাজার ব্যবহারকারীর হাতে যাচাই হয়নি। **প্রথম কয়েক মাসে
দু-একটা বাগ বেরোবে** — এটাই স্বাভাবিক, যেকোনো নতুন সিস্টেমেই হয়।

তাই আসল সুরক্ষা কোনো একটা বাগ না থাকা নয় — **রোজকার ব্যাকআপ**। ওটা থাকলে
সবচেয়ে খারাপ পরিস্থিতিতেও আপনি এক দিনের কাজ হারাবেন, ব্যবসা নয়।

বাগ পেলে যা পাঠাবেন:
1. কী করছিলেন (কোন পেজ, কোন বাটন)
2. স্ক্রিনশট
3. `sudo journalctl -u dreamfly -n 50` এর আউটপুট

## টাইমজোন — সবচেয়ে জরুরি সেটিং

সার্ভার যে সময় ধরে চলে, রিমাইন্ডারও সেই সময়েই বাজে। বিদেশ থেকে কেনা VPS
সাধারণত **UTC** তে চলে — ঢাকা UTC+6, তাই ফলোআপের রিমাইন্ডার **৬ ঘণ্টা দেরিতে**
আসবে।

`.env` ফাইলে এই লাইনটা থাকতেই হবে:

```
TZ=Asia/Dhaka
```

না থাকলে সিস্টেম চালু হওয়ার সময় নিজেই সতর্ক করবে:

```
WARNING: this server is running on UTC.
Follow-up and meeting reminders will fire at the wrong local time.
```

ঠিক থাকলে দেখাবে: `Timezone: Asia/Dhaka (UTC+6)`

## অটোমেটিক ব্যাকআপ (systemd timer)

হাতে `npm run backup` লেখার ভরসায় থাকবেন না — একদিন ভুলে যাবেন।

```bash
sudo cp scripts/dreamfly-backup.service /etc/systemd/system/
sudo cp scripts/dreamfly-backup.timer   /etc/systemd/system/
sudo systemctl daemon-reload
sudo systemctl enable --now dreamfly-backup.timer
```

প্রতি রাত ২টায় ব্যাকআপ হবে। সার্ভার বন্ধ থাকলে চালু হওয়ার পর ধরে নেবে।

কবে শেষ হয়েছে দেখতে:

```bash
systemctl list-timers dreamfly-backup
```

**cron ব্যবহার করলে** (`crontab -e`):

```
0 2 * * * cd /opt/dreamfly && TZ=Asia/Dhaka /usr/bin/npm run --silent backup >> /var/log/dreamfly-backup.log 2>&1
```

সার্ভিস ফাইলও দেওয়া আছে — `scripts/dreamfly.service`।

## রিভার্স প্রক্সির পিছনে চালালে

nginx / Caddy / Cloudflare সামনে থাকলে `.env`-এ দিন:

```
TRUST_PROXY=1
```

**সামনে প্রক্সি না থাকলে এটা দেবেন না।** এটা দেওয়া মানে সিস্টেম
`X-Forwarded-For` হেডারকে বিশ্বাস করবে — আর তখন যে কেউ নিজের হেডার পাঠিয়ে
রেট লিমিট ফাঁকি দিতে পারবে।

## পাসওয়ার্ড ভুলে গেলে / অ্যাডমিন লক হয়ে গেলে

একটা অ্যাকাউন্টে ১৫ মিনিটে ১০ বার ভুল পাসওয়ার্ড দিলে সেটা সাময়িকভাবে বন্ধ
হয়ে যায় (পাসওয়ার্ড অনুমান করা ঠেকাতে)। অপেক্ষা করতে না চাইলে সার্ভারে:

```bash
npm run admin -- --email you@company.com --password 'notun-password-2026'
```

এতে পাসওয়ার্ড বদলে যাবে আর ওই ইউজারের সব সেশন বন্ধ হয়ে যাবে।

## ব্যাকআপ থেকে ফেরানো

```bash
npm run backup -- --list                    # কী কী আছে দেখুন
sudo systemctl stop dreamfly                # সার্ভার বন্ধ করুন
npm run restore -- --latest --yes           # সবচেয়ে নতুনটা ফেরান
sudo systemctl start dreamfly
npm run doctor                              # যাচাই করুন
```

ফেরানোর সময় **ডেটাবেস আর আপলোড করা ডকুমেন্ট দুটোই** ফিরে আসে। কোন ডকুমেন্ট
ব্যাকআপেও না থাকলে সেটা নাম ধরে বলে দেবে।

বর্তমান ডেটাবেসটা মুছে যায় না — `backups/replaced/` ফোল্ডারে রাখা হয়, তাই
ভুল করে রিস্টোর করলে সেটাও ফেরানো যায়।

## ডিলিট বনাম আর্কাইভ

কাস্টমার, ফাইল, লিড, পার্টনার আর ইনভয়েস — এগুলো **মুছে যায় না, আর্কাইভ হয়**।

- আর্কাইভ করলে তালিকা, হিসাব আর রিপোর্ট থেকে সরে যায়
- সাথে যা যা লাগানো ছিল (পেমেন্ট, ডকুমেন্ট, ইতিহাস) সব ঠিক থাকে
- শুধু **অ্যাডমিন** আর্কাইভ করতে পারে, আর অ্যাডমিনই ফেরাতে পারে
- যে ইনভয়েসে টাকা জমা আছে সেটা আর্কাইভ **করা যাবে না** — আগে রিফান্ড দিতে হবে

টাকা ফেরত দিতে হলে পেমেন্ট **মুছবেন না** — ইনভয়েস খুলে **Refund** বাটন ব্যবহার
করুন। তাহলে "টাকা এসেছিল" আর "টাকা ফেরত গেছে" — দুটোই খাতায় থাকবে।
